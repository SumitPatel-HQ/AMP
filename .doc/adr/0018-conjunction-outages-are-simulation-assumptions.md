# Conjunction evidence describes a prediction and an assumed payload outage

We reuse `SATELLITE_UNAVAILABLE` with an optional, complete `conjunction` group. The event stores the source attribution, encounter identity, matched and counterpart NORAD identities, UTC TCA, miss distance in kilometers, source maximum probability, threshold, policy version, and positive pre/post padding in seconds. Evidence-free payloads keep their existing wire shape and validation. Accepted events are the replay unit (ADR-0002); neither planning nor reconstruction reads a source report or accesses the network.

`socrates-outage-v1` compares the supplied normalized maximum probability against an explicitly recorded threshold (the proposed default is 0.0001). That value is a simulation selection policy, not a measured collision outcome, operational advice, or proof of a real maneuver. Ticket E-01 uses explicitly synthetic evidence and makes no claim about SOCRATES report conversion or historical provenance; source representation, report integrity, availability dates, and archiving belong to E-02.

The author supplies an assumed half-open interval exactly equal to TCA minus pre-padding through TCA plus post-padding. MissionSession validates evidence, stored Satellite orbital identity, full horizon containment, injection no later than interval start, and duplicate encounter/Satellite identity before mutation. Distinct encounters remain separate records; the existing planner applies all intervals, giving their union without counting an imaging action twice. No orbit change, fuel use, delta-v, or maneuver confirmation is modeled.

`COLLISION_AVOIDANCE_OUTAGE` means recorded conjunction unavailability blocked the previous imaging placement. It is not inferred from arbitrary plan differences. An earlier manual outage and base unavailability retain their ordinary reason; unrelated constraint violations retain their reasons. A dropped action may report conjunction displacement when the remaining windows fail availability or timing, while resource failure keeps its ordinary reason. Traces link the overlapping recorded evidence and name counterparts. Frozen conflicts appear in Impact.reason_codes alongside frozen_action_ids, outside invalid_unfrozen_action_ids: replanning never moves, drops, or recosts frozen actions (ADR-0003).

## E-02 source boundary

The separate `amis.conjunctions` developer module archives the documented SOCRATES Plus CSV as original bytes and verifies its checksum before parsing. UTC TCA and kilometer range are already in source units; maximum probability scientific notation is a fraction, never a percentage. Missing or unsupported probability has no qualifying value and produces a diagnostic. Pair/TCA identity is canonical across orientation, while source object names and orientation remain in generated inputs. Conflicting selected encounters fail. Matching uses stored orbital NORAD identities and explicit mappings for identity reuse.

The 2026-10-26 provider policy states a 10–11 hour update cadence. The explicit fetch defaults to a conservative 11-hour interval from that check, configurable after policy revalidation, persists cooldown before the request, stops on non-200 responses without redirects/retries, and preserves Retry-After extensions. Runtime code never imports the fetch. Publication and coverage are nullable rather than inferred from retrieval or HTTP Last-Modified. Without established publication, retrieval is the availability bound. Generated inputs include source URL/hash, mapping, encounter identity, policy, threshold, padding, and intended injection instant. A complete artifact is published exclusively after all validation.

The bundled dated Example uses actual archived FLOCK 4G-1/STARLINK-30895 predictions, a separately fetched compatible orbital snapshot, and explicitly hypothetical requests and sensor policy. One-hour padding is a training assumption. Replay reads Scenario plus accepted input evidence offline and separately replans; persistence reconstructs from stored events without the report.

Source conversion supports a complete `EncounterOutagePolicy` per canonical encounter identity, with optional complete scalar defaults for compatibility. Each injection and padded interval is checked independently. Archive loading treats the recorded next-fetch time as provenance, validating timestamp ordering without imposing the current developer fetch cadence. The domain `outage_interval` calculation is shared by source conversion and evidence validation. Overlapping conjunction traces retain a primary `event_id` for compatibility and list every causal event id and counterpart in both the message and `metadata["conjunction_events"]`. Standalone replay scripts and lifecycle tests cover conjunction behavior without a special synthetic registration in the shared evaluation runner.
